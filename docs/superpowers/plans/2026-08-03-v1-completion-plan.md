## 0. 이 문서의 운영 규칙

이 문서는 V1 작업의 단일 실행 기준이다. 채팅 내용은 요구를 결정하는 입력이지만, 실제 구현 상태·승인 범위·다음 작업은 반드시 이 문서에 반영한 뒤 진행한다.

우선순위는 다음과 같다.

1. 사용자의 최신 직접 지시
2. 프로젝트 `AGENTS.md`
3. 이 V1 완성 구현계획서
4. 최신 코드와 검증 증거
5. 구 계획·구 핸드오프·구 목업

새 세션, 컨텍스트 압축, handoff, 모델 변경 뒤에는 `AGENTS.md`와 이 문서를 처음부터 끝까지 다시 읽는다. 이후 Git 상태와 코드를 대조하고 차이를 먼저 보고한다. 채팅 요약만으로 상태를 복구하거나 다음 작업을 고르지 않는다.

상태 용어는 아래 의미로만 사용한다.

- `미구현`: 사용자 요구를 충족하는 코드 또는 데이터 구조가 없다.
- `부분 구현`: 일부 흐름만 동작하거나 사용자 요구와 다른 제약이 남아 있다.
- `구현`: 코드가 존재하지만 자동·화면·운영 검증이 모두 끝난 것은 아니다.
- `자동 검증`: 대상 테스트·타입·lint·빌드 등 자동 검사가 통과했다.
- `화면 검증`: 실제 제품 화면에서 사용자가 수행할 동작을 확인했다.
- `운영 검증`: 배포된 Worker와 운영 데이터로 확인했다.
- `완료`: 해당 실행 단위의 모든 완료 기준과 사용자 승인이 끝났다.

하위 작업 하나가 끝나도 실행 단위 또는 Phase 전체를 `완료`로 확대하지 않는다. 새 불일치가 발견되면 구현보다 먼저 아래 원장과 다음 실행 단위를 갱신한다.

계획 내용이 완료되거나 방향이 바뀌면 이전 문장을 삭제하지 않는다. 원래 문장에는 취소선을 적용하고 바로 다음 줄에 새 상태·근거·날짜를 적는다. 단순 오탈자 수정은 이력 없이 고칠 수 있지만, 범위·승인·상태·완료 기준 변경은 반드시 이 규칙을 적용한다.

## 3. Phase 0: 관리자 인증 오류 복구

> 상태: 코드 수정·회귀 테스트·`main` push·사용자/관리자 Worker 배포 완료. 최신 관리자 PWA의 여행 편집창 최종 확인만 남음.

### 문제

- 관리자 Worker의 정적 화면은 열려도 Cloudflare Access 세션이 만료되면 `/api/*` 요청이 로그인 주소로 이동한다.
- 브라우저 `fetch`에서는 이 이동이 CORS 오류가 되어 단순 `Failed to fetch`로 보였다.
- 여행 직접 주소에서는 관리자 인증 오류까지 참여자 세션 만료로 처리해 `/pair`로 잘못 이동할 수 있었다.
- 참여자 명단 Promise 거절이 잡히지 않아 로딩이 끝나지 않는 경로가 있었다.

- `Failed to fetch` 대신 `관리자 로그인이 필요합니다`와 `관리자 다시 로그인` 버튼이 보인다.
- 로그인 후 `continue`에 기록된 여행 편집 또는 관리 화면으로 돌아온다.

- **Google Weather API:** 호주의 current·hourly·daily·history·alerts를 지원하고 월 10,000 successful events 무료다. Cloud billing과 API key가 필요하며 이후 종량 과금된다. current·hourly 캐시는 최대 1시간이고 자체 Worker hard limit 외에 billing account 전체 quota를 별도 관리해야 한다.

### 2026-08-11 · Phase 4 승인 전 백업·복원 준비

- Cloudflare D1 공식 문서와 현재 설치된 Wrangler `4.114.0`을 대조했다. 전체 운영 SQL export는 `wrangler d1 export <database> --remote --output=<file>`, 별도 테스트 D1 복원은 `wrangler d1 execute <test-database> --remote --file=<file>` 경계를 사용한다. 실제 export·import·원격 조회는 실행하지 않았다.
- 공식 `age`는 Windows 설치와 공개키 recipient 암호화를 지원하지만 현재 작업 환경에는 `age`·`age-keygen`이 설치돼 있지 않다. 도구 설치, 키 생성, 개인키 보관 위치는 별도 승인 전에는 실행하지 않는다.
- 현재 앱의 Google Drive 연결은 브라우저에서 `drive.file` access token을 일시 발급받아 메모리에만 보관하며 refresh token을 저장하지 않는다. 따라서 이 인증을 무인 PowerShell 백업에 재사용할 수 없다. V1 첫 검증은 암호화 파일의 **수동 Drive 업로드**가 가장 작은 범위이고, 자동 업로드는 별도 OAuth 도구·서비스 계정·토큰 보관 정책을 승인한 뒤 분리한다.
- **추천 승인안:** `age` 공개키 암호화, 개인키는 Drive·Git·프로젝트 밖의 암호화 저장소와 별도 오프라인 복구 사본에 보관, 첫 백업은 수동 실행·수동 Drive 업로드, 복원은 새 테스트 D1만 사용한다. 개인키 보관 위치·`age` 설치·백업 폴더·테스트 D1 생성·운영 export는 사용자가 승인해야 한다.
- 공식 근거: [Cloudflare D1 import/export](https://developers.cloudflare.com/d1/best-practices/import-export-data/), [Wrangler D1 commands](https://developers.cloudflare.com/d1/wrangler-commands/), [age 공식 저장소](https://github.com/FiloSottile/age), [Google Drive files.create](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/create).
