# 둘만의 여행 가이드북 1단계 설계

- 작성일: 2026-07-27
- 상태: 사용자 승인 설계
- 대상 저장소: `syd-guide`
- 구현 대상: 1단계 공동 여행 기본앱

## 1. 배경

현재 프로젝트는 홈만 CDN React를 사용하고 나머지는 정적 HTML로 구성되어 있다. 여행 정보가 HTML과 JavaScript에 직접 들어 있어 여행지를 추가하거나 둘이 동시에 수정하기 어렵다.

기존 시드니 가이드의 콘텐츠는 유지하되, 디자인은 완전히 새롭게 설계한다.

- 보기 편안한 여백과 명확한 정보 계층
- 상용 여행 앱처럼 직관적인 카드형 화면과 일관된 컴포넌트
- 따뜻하고 차분한 색상 조합을 바탕으로 한 현대적인 UI
- 하버 틸 포인트 색상은 강조 요소에만 제한적으로 사용
- 편집형 여행 잡지 분위기와 겹쳐진 카드 중심의 기존 표현은 사용하지 않음
- 상단 내비게이션과 하단 빠른 메뉴는 모바일 앱 사용성을 기준으로 새롭게 구성한다.

- 따뜻한 종이색 배경
- 하버 틸 포인트 색상
- 편집형 여행 잡지 분위기
- 겹쳐진 카드
- 고정 상단 메뉴와 빠른 하단 메뉴

새 제품은 시드니 전용 사이트가 아니라 여러 여행을 보관하는 `둘만의 여행 가이드북`이다.

## 2. 전체 목표

하나의 설치형 PWA(홈 화면에 설치하는 웹앱)에서 다음 흐름을 지원한다.

1. 여행 전: 둘이 일정, 장소, 예약, 준비물을 계획한다.
2. 여행 중: 오늘 일정과 예약을 빠르게 확인하고 오프라인에서도 사용한다.
3. 여행 후: 사진과 방문 장소를 연결해 둘만의 추억을 보관한다.

전체 목표는 유지하되 구현은 세 단계로 나눈다.

### 1단계: 공동 여행 기본앱

- 여행별 생성, 수정, 삭제, 복구
- 일정, 장소, 예약, 준비물, 공동 메모
- 커플 투표
- 오늘 한 장
- 오프라인 열람과 수정
- 두 기기 동기화와 충돌 처리
- Google 지도 연결
- 개인별 ChatGPT 또는 Gemini 앱 연결

### 2단계: AI와 공동 비용

- Codex가 조사한 인기 맛집과 액티비티 추천
- 거리, 영업시간, 고정 예약을 고려한 AI 동선 추천

- 결제자, 카테고리, 통화, 정산 기록
- 영수증 AI 분석 후 원본 즉시 삭제
- 예약 화면과 문자 캡처 AI 분석
- 비용 CSV와 일정 PDF 내보내기

### 3단계: 추억

- 여행 사진 업로드
- 장소별 추억 지도
- 날짜별 사진 타임라인
- AI 여행 이야기
- 둘만의 PDF 여행책

## 4. 1단계 범위

### 4.1 여행 서재

여행을 카드로 표시한다.

- 제목
- 여행지
- 시작일과 종료일
- 예정, 여행 중, 완료 상태
- 대표 이미지
- 최근 수정 시간

둘 다 여행을 생성하고 수정할 수 있다. 삭제는 즉시 영구 삭제하지 않고 30일 휴지통으로 이동한다. 둘 다 복구할 수 있다. 30일이 지난 항목은 자동 삭제한다.

### 4.2 여행 내부

여행 화면은 인기 여행 플래너 앱을 비교해 계획, 예약, 현장 사용, 공동 편집에 필요한 기능을 보완한 다음 탭으로 구성한다.

- Wanderlog: 일정·장소·예약·지도·공동 편집을 한 화면에서 연결하는 데 강점이 있다.
- TripIt: 이메일 예약 정보를 한곳에 모으고 교통·숙소 예약을 시간순으로 보여주는 데 강점이 있다.
- Google Maps: 장소 저장, 지도 기반 탐색, 이동 경로 확인에 강점이 있다.
- Roadtrippers: 장소 사이의 거리와 이동 순서를 지도에서 조정하는 데 강점이 있다.
- PackPoint: 날씨와 여행 기간을 고려한 개인별 준비물 추천에 강점이 있다.
- Splitwise·Tricount: 공동 비용 기록과 사용자별 정산에 강점이 있으나 1단계에서는 비용 기능을 넣지 않는다.

위 비교를 반영해 1단계에는 장소와 일정을 지도에서 확인하는 기능, 고정 예약을 기준으로 한 일정 구분, 개인별 준비물과 공동 준비물 구분, 검색·필터·정렬, 변경 내역 확인을 포함한다. 이메일 자동 예약 가져오기, 실시간 교통·이동시간, 날씨 기반 추천, 비용 관리, AI 일정 재배치는 후속 단계로 둔다.

1. `오늘`: 오늘 일정, 다음 예약, 미완료 준비물, 오늘 메모, 현재 위치 기준 빠른 지도 링크, 일정·예약 변경 알림
2. `일정`: 날짜별 시간, 장소, 메모, 순서, 이동 구간, 고정 예약, 완료 표시, 지도에서 전체 동선 보기
3. `지도`: 일정과 저장한 장소를 지도에 표시하고 날짜·분류·상태별로 필터링, 장소 상세 열기, 일정에 추가
4. `장소`: 맛집, 카페, 명소, 숙소, 교통 거점, 찜·보류·방문 완료 상태, 개인별 저장, 커플 투표, 일정에 추가
5. `예약`: 항공, 숙소, 입장권, 투어, 교통, 예약별 날짜·시간·장소·예약번호·링크·문서, 고정 일정 표시
6. `준비물`: 둘이 공유하는 체크리스트, 개인별 준비물, 담당자 지정, 수량·메모, 준비 완료 상태
7. `메모`: 여행 전체 또는 특정 일정·장소·예약에 연결한 메모, 사진·링크 첨부, 개인 메모와 공동 메모 구분
8. `더보기`: 여행 설정, 검색·필터, 활동 기록, 휴지통, 오프라인 상태, 동기화 상태, AI 질문 만들기

모든 탭에서 장소명·메모·예약 정보를 검색할 수 있으며, 목록은 날짜·카테고리·상태·수정 시간으로 정렬한다. 지도와 예약 원문은 오프라인에서도 최근 저장 내용을 열람할 수 있고, 외부 지도·예약 링크는 온라인 연결 시 연다.
### 4.3 일정 편집

- 날짜와 시간 추가
- 장소 연결
- 순서 이동
- 메모 작성
- 완료 표시
- 고정 예약 표시

- 수정자와 수정 시간 표시

1단계에서는 AI가 일정을 자동 재배치하지 않는다.

### 4.4 장소

- 맛집, 카페, 명소, 숙소 분류
- 찜, 보류, 방문 완료 상태
- 일정에 추가
- 주소와 Google 지도 링크
- 개인 메모와 공동 메모

### 4.5 커플 투표

각 장소와 활동에 다음 중 하나를 선택한다.

- 꼭 가기
- 괜찮음
- 별로

두 사람의 선택을 나란히 보여준다. 둘 다 `꼭 가기`를 선택한 항목은 `확정 후보`로 표시한다.

### 4.6 예약

- 예약 종류
- 업체명
- 날짜와 시간
- 예약번호
- 결제 상태
- 링크
- 메모

예약번호는 기본 화면에서 일부를 가리고 사용자가 눌렀을 때만 전체를 표시한다.

### 4.7 오늘 한 장

앱을 열었을 때 현장에서 필요한 정보만 먼저 보여준다.

- 다음 일정
- 다음 고정 예약
- 미완료 준비물
- 오늘 메모
- Google 지도 열기

정확한 이동시간과 AI 출발 추천은 2단계 범위다.

### 4.8 AI 도우미 연결

ChatGPT와 Gemini API를 앱 안에 넣지 않는다. 각 기기에서 선택한 AI 앱으로 연결한다.

- 사용자가 ChatGPT 또는 Gemini를 선택한다.
- 선택값은 해당 기기에만 저장한다.
- 여행 전체, 오늘 일정, 선택한 장소 중 질문 범위를 고른다.
- 앱이 여행 문맥을 포함한 질문을 만든다.
- 질문을 클립보드에 복사한다.
- 선택한 AI의 앱 또는 웹을 연다.

AI 선택값과 질문 기록은 상대방 및 D1에 저장하지 않는다.

## 5. 사용자와 권한

### 5.1 관리자

관리자는 소유자 한 명이다.

- Cloudflare Access 이메일 로그인
- 여자친구 초대 발급
- 연결 기기 목록 확인
- 연결 기기 해제
- 일반 여행 데이터 생성, 수정, 삭제, 복구

### 5.2 여자친구

여자친구는 이메일 계정을 만들지 않는다.

- QR 또는 1회용 링크로 기기 연결
- 일반 여행 데이터 생성, 수정, 삭제, 복구
- 일정, 장소, 예약, 준비물, 메모, 투표 편집
- 관리자 설정, 새 초대 발급, 기기 해제 불가

## 6. 초대와 기기 연결

QR과 링크는 같은 1회용 초대 토큰을 사용한다.

1. 관리자가 초대를 생성한다.
2. QR과 링크를 함께 표시한다.
3. 초대는 10분 후 만료된다.
4. 여자친구가 QR을 스캔하거나 링크를 연다.
5. Worker가 토큰을 검증하고 기기 세션으로 교환한다.
6. 사용한 초대 토큰은 즉시 폐기한다.
7. 주소에서 초대 토큰을 제거한다.
8. 기기에는 `HttpOnly`, `Secure`, `SameSite` 쿠키를 저장한다.

기기 세션은 90일 동안 사용하지 않으면 만료된다. 정상 사용 시 만료일을 갱신한다. 관리자는 언제든 세션을 해제할 수 있다. 브라우저 데이터 삭제나 휴대폰 변경 시 새 초대가 필요하다.

서버에는 초대 토큰과 세션 토큰 원문을 저장하지 않고 해시만 저장한다.
초대 토큰은 추측할 수 없는 256비트 난수로 생성한다. 초대 링크를 처음 연 기기가 권한을 얻으므로 관리자는 링크를 여자친구에게만 전달해야 한다.

## 7. 배포 경계

관리자와 여자친구의 인증 방식이 다르므로 보호 경계를 분리한다.

```text
관리자 호스트
  Cloudflare Access 보호
  관리자 전용 초대·기기 관리
  일반 여행 편집

공유 앱 호스트
  PWA 정적 화면
  기기 세션이 있어야 여행 API 사용
  일반 여행 편집
```

두 호스트는 같은 React 컴포넌트와 D1 데이터베이스를 사용한다. 정적 앱 화면이 열리더라도 유효한 Access 신원이나 기기 세션이 없으면 여행 데이터 API는 항상 거부한다.

관리자 API는 Cloudflare Access가 추가한 JWT의 서명, 대상, 만료를 Worker에서 다시 검증한다.

## 8. 기술 구조

### 8.1 프런트엔드

- Vite
- React
- TypeScript
- PWA 서비스 워커
- IndexedDB 오프라인 저장소

### 8.2 Cloudflare

- Workers: 정적 앱과 API
- Access: 관리자 인증
- D1: 여행 데이터와 세션 메타데이터
- Workers AI: 2단계 AI 기능
- R2: 3단계 사진

유료 기능은 사용하지 않는다. 무료 한도를 넘으면 유료 전환하지 않고 기능을 중단하고 사용자에게 알린다.

### 8.3 코드 경계

```text
src/
  app/          앱 시작과 라우팅
  pages/        화면 조립
  components/   공통 UI
  features/     여행, 일정, 장소, 예약, 체크, 메모, 투표
  services/     API, 오프라인, 동기화
  types/        공유 데이터 타입

worker/
  routes/       API 경로
  auth/         Access와 기기 세션 검증
  db/           D1 쿼리
  validation/   외부 입력 검증
```

원칙:

- 파일 하나에 책임 하나
- 화면 파일은 기능을 조립하고 업무 로직을 가지지 않음
- 여행 내용과 화면 코드를 분리
- 기능 파일은 보통 100~250줄 목표
- 10줄짜리 무의미한 파일 분할 금지
- 거대한 단일 `app.js`, HTML, CSS, JSON 금지
- 공통 컴포넌트는 실제로 두 곳 이상에서 쓸 때만 생성

## 9. D1 데이터

### 9.1 인증

- `pair_invites`: 1회용 초대, 만료, 사용 여부
- `device_sessions`: 해시된 세션, 만료, 해제 여부
- `members`: 관리자와 여자친구 역할

### 9.2 여행

- `trips`: 여행 기본 정보와 삭제 시각
- `trip_days`: 여행 날짜
- `schedule_items`: 일정
- `places`: 장소
- `bookings`: 예약
- `check_items`: 준비물
- `notes`: 공동 메모
- `votes`: 장소별 사용자 선택
- `activity_logs`: 주요 변경 기록

모든 여행 데이터 요청은 사용자 역할과 여행 참여 여부를 확인한다. 클라이언트가 보낸 사용자 ID나 역할을 신뢰하지 않는다.

## 10. 오프라인과 동기화

### 10.1 로컬 저장

최근 여행의 다음 데이터를 IndexedDB에 저장한다.

- 여행 기본 정보
- 일정
- 장소
- 예약
- 준비물
- 메모
- 투표
- 전송 대기 중인 수정

### 10.2 동기화 시점

- 앱 시작
- 앱이 다시 전면에 표시될 때
- 네트워크가 복구될 때
- 화면이 열린 동안 15초 간격
- 사용자가 직접 새로고침할 때

### 10.3 충돌

각 수정 가능한 항목에 버전 번호를 둔다.

1. 수정 요청이 현재 버전과 같으면 저장한다.
2. 서버 버전이 더 높으면 `409 Conflict`를 반환한다.
3. 앱은 내 수정과 최신 내용을 함께 보여준다.
4. 사용자가 `내 수정 유지` 또는 `최신 내용 사용`을 선택한다.

충돌을 자동으로 덮어쓰지 않는다.

## 11. 오류 처리

### 오프라인

- 상단에 오프라인 상태 표시
- 수정은 로컬 대기열에 저장
- 재연결 후 자동 전송
- 실패한 항목은 사용자에게 표시하고 수동 재시도 제공

### 로그인 또는 세션 만료

- 작성 중인 내용을 로컬에 보존
- 관리자에게 재로그인 안내
- 여자친구에게 새 초대 필요 여부 안내

### 외부 링크

- Google 지도나 AI 앱이 열리지 않으면 웹 주소 제공
- 클립보드 복사가 실패하면 생성한 질문을 화면에 표시

### 삭제

- 일반 삭제는 휴지통 이동
- 복구 가능 기간과 자동 삭제 날짜 표시

## 12. 보안과 개인정보

- API 키, Access 토큰, 세션 토큰을 Git에 저장하지 않음
- 세션 쿠키를 JavaScript에서 읽을 수 없게 설정
- 세션 쿠키에 `SameSite=Strict` 적용
- 쓰기 API에서 요청 출처 검증
- 모든 쓰기 API에서 입력값과 권한 검증
- 예약번호는 기본 화면에서 마스킹
- 여권번호, 카드번호, 주민등록번호 저장 기능 없음
- 활동 로그에 인증값과 민감한 예약 원문을 기록하지 않음
- AI 질문에는 사용자가 선택한 여행 문맥만 포함
- ChatGPT 또는 Gemini 선택값은 기기에만 저장

기기를 해제하면 서버 API 접근은 즉시 차단한다. 이미 오프라인으로 저장된 데이터는 원격으로 삭제할 수 없으므로 앱이 다시 연결되는 즉시 로컬 캐시를 지운다. 휴대폰 자체 잠금은 필수 전제로 둔다.

## 13. 무료 운영 원칙

- Cloudflare 무료 플랜만 사용
- 유료 플랜 자동 전환 없음
- 무료 한도 초과 시 쓰기 또는 AI 기능을 중단하고 안내
- 1단계에는 R2 사진 저장과 Workers AI 호출 없음
- 2단계 AI 기능은 일일 무료 한도 내에서만 실행
- 3단계 R2 사진은 앱 자체 총량을 5GB로 제한
- 외부 유료 지도 API 사용 없음

Cloudflare 한도와 모델은 구현 시작 및 배포 직전에 공식 문서로 다시 확인한다.

## 15. 1단계 완료 조건

다음 흐름을 실제 두 사용자 세션에서 확인해야 완료다.

```text
관리자 로그인

→ 재연결 동기화
→ 여행 삭제와 복구
→ 관리자 기기 해제
→ 해제된 기기 접근 차단
```
