# 우리만의 여행 가이드북 - 모바일 Trip Control 리디자인

> 확정일: 2026-07-30
>
> 상태: 화면별 사용자 승인 완료, 구현 계획 작성 전 최종 명세 검토 대기
>
> 범위: 기존 Task 14-20 구현 위에 적용할 모바일 우선 UX/UI 기준

## 1. 목적과 우선순위

앱은 여행 기록용 가이드북이 아니라 여행 중 계속 열어 보는 개인 여행 제어판이다.

우선순위는 다음과 같다.

1. 지금 필요한 다음 행동을 바로 연다.
2. 일정, 장소, 예약, 비용을 같은 여행 맥락 안에서 찾는다.
3. 두 사람이 쓴 비용과 예약 파일을 잊지 않고 관리한다.
4. 귀국 뒤에는 실제 여행 사진으로 여행을 남긴다.

모바일이 기준 화면이다. PC는 같은 데이터와 기능을 넓은 화면에 보조적으로 표시한다.

## 2. 승인된 전역 방향

- 시각 방향: 밝고 가벼운 시드니. 밝은 배경, 하버 틸(teal) 포인트, 둥근 카드, 야외에서도 읽기 쉬운 대비를 사용한다.
- 정보 방향: 한 화면에 모든 것을 넣지 않는다. 가장 중요한 다음 행동을 먼저 보여 주고, 세부 정보는 bottom sheet(아래에서 올라오는 상세 패널) 또는 목록으로 연다.
- 터치: 핵심 버튼과 선택 영역은 최소 44 x 44 CSS px이다.
- 모션: 짧은 opacity/transform 전환만 사용하고 reduced motion 설정에서는 fade만 남긴다.
- 기존 `today | schedule | map | tools` 하단 메뉴와 오프라인 snapshot/outbox 동작은 유지한다.
- Google Maps는 상세 길찾기 외부 연결만 유지한다. 이번 리디자인에서 Places API, 항공편 API, 웹 스크래핑을 추가하지 않는다.

## 3. 화면별 승인 설계

### 3.1 오늘: 여행 중 동선 보드

여행 중 기본 첫 화면은 `오늘의 동선`이다.

- 상단: 현지 날짜, Day, 오늘 사용한 총액, 다음 일정.
- 중단: 오늘 장소 핀과 이동 순서를 보여 주는 지도.
- 하단: 시간순 일정 타임라인. 목록 보기는 같은 날짜의 전체 일정을 크게 볼 수 있다.
- 일정 순서는 사용자가 직접 바꾼다. 순서 변경은 지도 핀·경로·이동 간격에 즉시 반영한다.
- 단계별 대표 행동은 여행 전 `준비 추가`, 여행 중 `지출 추가`, 귀국 후 `사진 추가`로 바뀐다.

### 3.2 일정: 지도 기본, 목록 확장

- 기본은 지도와 당일 경로를 보는 화면이다.
- `목록 보기` 또는 bottom sheet를 위로 올리면 같은 날의 전체 일정 목록을 본다.
- 장소를 누르면 지도 위 bottom sheet에 저장된 사용자 입력 정보가 열린다.
- 내부 장소 상세에는 이름, 주소, 수동 입력 영업시간, 메모, 사진, 연결 일정, 편집, Google Maps 길찾기 링크를 둔다.
- 외부 API로 평점·실시간 영업정보를 새로 넣지 않는다.

### 3.3 지출: 10초 빠른 입력

여행 중 대표 행동으로 아래 필드를 같은 bottom sheet에서 입력한다.

| 필드 | 규칙 |
|---|---|
| 지출 이름 | 사용자가 기억할 이름. 예: `브런치 · Single O` |
| 금액과 통화 | 금액 필수, 여행 기본 통화 표시 |
| 카테고리 | 식비, 교통, 입장권, 쇼핑 등 |
| 결제자 | 여행 멤버 중 한 명 선택 |
| 비용 구분 | 개인 비용 또는 함께 낸 비용 1/N |
| 결제 수단 | 카드 또는 현금 |

- 함께 낸 비용만 정산 후보에 반영한다.
- 카드·현금 사용액은 나중에 분리해 볼 수 있다.
- 매일 밤 `오늘 쓴 돈을 정리할까요?` 알림은 미기록 지출을 빠른 입력으로 연결한다.
- 실제 기기 알림 권한, 웹 푸시와 발송 시점은 구현 계획에서 별도로 검증하고 사용자의 배포 승인을 받은 뒤 적용한다.

### 3.4 출발 전: 준비 현황

출발 전에는 예약 타임라인보다 `남은 준비`를 먼저 보여 준다.

- 상단: 출발까지 남은 날짜와 필수 준비 개수.
- 본문: 여권 만료일, 숙소 예약 확인서, 항공권 입력, 필수 예약 등 미완료 항목.
- 하단: 이미 결제한 항공권·숙소·예약금 등 준비 비용 요약과 준비 항목 추가.
- 완료한 항목은 체크 상태와 짧은 요약을 유지한다.

### 3.5 여행 중: 예약 보관함

출국 시각 이후 귀국 도착 시각 전에는 같은 진입점이 `예약 보관함`으로 전환된다.

- 오늘 필요한 예약을 가장 먼저 보여 준다.
- 항공편, 숙소, 투어, 입장권을 날짜순 타임라인으로 표시한다.
- 각 예약에 체크인 상태와 사진 또는 PDF 첨부를 붙인다.
- 항공편은 온라인 체크인 전/완료 상태를 보이고, 완료 뒤 탑승권 사진 또는 PDF를 저장할 수 있다.
- 투어·입장권·숙소 바우처 사진은 해당 예약 카드에 붙여 한곳에서 본다.

### 3.6 귀국 후: 사진과 대표 사진

- 여행 전 대표 이미지는 저작권 문제 없는 시드니 기본 이미지다.
- 귀국 후 대표 이미지는 사용자가 실제로 찍은 사진에서만 고른다.
- 사진은 사진 전용 Google Drive 폴더에서 가져온다.
- 기기 내 AI는 선명도, 흔들림, 밝기, 풍경 구성을 기준으로 후보를 추천한다.
- 추천은 자동 확정하지 않는다. 사용자가 후보를 고르고 대표 사진으로 확정한다.
- 미리보기에서 자르기·밝기 편집만 제공한다. 원본은 변경하지 않는다.
- 음악, 자동 영상 생성, 외부 AI로 사진 업로드는 이번 범위에서 제외한다.

## 4. 단계 전환 규칙

기존 Journey Phase Model을 UI 전환 기준으로 사용한다.

| 단계 | 대표 홈 행동 | 준비/예약 진입점 |
|---|---|---|
| 여행 전 | 준비 추가 | 준비 현황 |
| 여행 중 | 지출 추가 | 예약 보관함 |
| 귀국 후 | 사진 추가 | 여행 사진 |

- 단계는 출국편의 예정 출발 시각부터 귀국편의 한국 도착 예정 시각까지를 기존 모델대로 계산한다.
- 시간 경계가 없거나 잘못되면 기존 여행 상태값으로 표시하고, 항공편 시각을 보완하도록 안내한다.
- UI 단계 전환은 파생 상태다. 기존 오프라인 snapshot과 동기화 규칙을 바꾸지 않는다.

## 5. 데이터 및 경계

- 앱의 예약·일정·장소·비용 데이터는 기존 공통 데이터 모델을 계속 사용한다.
- 항공편은 사용자가 직접 입력한 데이터만 사용한다. 자동 항공정보 조회는 구현하지 않는다.
- 예약 첨부는 예약 데이터에 연결하되, 파일 원본의 저장 위치와 접근 권한은 기존 Google Drive 사진 흐름과 분리해 구현 계획에서 확정한다.
- 여행 대표 사진의 원본은 사진 전용 Google Drive에 두고, 앱에는 필요한 메타데이터와 선택 상태만 저장한다.
- API 키, OAuth token, Drive 인증 정보는 프론트엔드나 저장소에 노출하지 않는다.

## 6. 이전 설계와의 우선순위

이 문서는 `docs/superpowers/specs/2026-07-29-final-product-design.md`의 UX/UI 우선순위를 다음처럼 갱신한다.

- 여행 전 홈은 큰 감성 커버보다 준비 현황과 남은 행동을 우선한다.
- 여행 중 홈은 다음 일정 3개 카드보다 오늘 동선 보드(지도 + 타임라인)를 우선한다.
- 귀국 후 미디어는 private R2 복사본 및 추억 쇼츠보다 사진 전용 Google Drive와 기기 내 후보 추천을 우선한다.
- 기본 음악, 자동 쇼츠 구성, MP4 생성은 이번 범위에서 제외한다.

기존 데이터 보안, 오프라인, 접근성, 개인 항목의 파트너 비노출 규칙은 그대로 유지한다.

## 7. 수용 기준

- 390 px 모바일에서 오늘, 일정, 지출, 준비/예약, 사진 화면이 가로 넘침 없이 읽힌다.
- 1440 px PC에서 같은 화면이 기능을 잃지 않고 보조적으로 확장된다.
- 오늘 화면에서 다음 일정, 지도 동선, 타임라인을 모두 확인할 수 있다.
- 일정 목록의 순서를 바꾸면 지도와 이동 정보가 같은 순서로 바뀐다.
- 지출은 이름, 결제자, 개인/1/N, 카드/현금을 저장할 수 있다.
- 출발 전에는 준비 현황, 여행 중에는 예약 보관함이 표시된다.
- 예약 카드에서 이용권 사진 또는 PDF를 열고 추가할 수 있다.
- 귀국 뒤 실제 여행 사진 후보 중 하나를 대표 사진으로 고를 수 있다.
- 야간 지출 알림과 Drive 인증 실패 시에도 지출 수동 입력과 기존 여행 데이터 확인은 막히지 않는다.
- 기존 일정, 장소, 예약, 준비물, 메모, 오프라인 동기화에 회귀가 없다.

## 8. 구현 전 확인 사항

1. 예약 사진/PDF의 실제 저장 위치와 접근 권한을 Google Drive 흐름에 맞춰 확인한다.
2. 야간 지출 알림을 local notification으로 할지, 웹 푸시로 할지와 권한 안내 시점을 승인받는다.
3. 기존 Today, Schedule, Tools의 실제 컴포넌트 경계를 다시 읽고 최소 변경 파일 목록을 정한다.
4. 구현 전 Astryx 구성요소와 토큰을 확인해 기존 앱 스타일을 해치지 않는 방식을 확정한다.
